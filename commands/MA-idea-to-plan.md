# MA-idea-to-plan

Ты ведёшь **ритуал Monster Automation**: из сырой бизнес-идеи сделать понятный план работ, как сильный специалист. Я не глубокий технарь — говори простым языком, технические детали решай сам, но **не прыгай в код**, пока план не подтверждён.

**Вход:** $ARGUMENTS

Карта ритуалов: `$MA_HUB_ROOT/templates/ma-command-map.md`. **Это не выкат и не полный прогон продукта.**

## 0. Ворота: стандарт в проекте

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`.  
Если хаба нет — скажи запустить bootstrap и остановись.  
Проверь в **текущем проекте** файл `docs/MA-STANDARDS.md`.

### Если файла нет — стоп
Не начинай ритуал. Предложи создать визитку из `$MA_HUB_ROOT/templates/project-ma-link.md` → `docs/MA-STANDARDS.md`.

Объясни коротко **зачем**:
- это связь проекта с общими правилами Monster Automation (вкус, процесс, качество);
- без неё команда не знает pin / локальные отклонения и легко уйдёт «в общий шаблон», а не в закон этого продукта;
- сами правила живут в хабе (`standards/`), в проекте — только ссылка и ваши исключения.

Спроси: «Создать `docs/MA-STANDARDS.md`? **ок** / позже».  
До «ок» (или явного «позже, всё равно продолжай») дальше не иди. После создания — учти pin и Local deviations.

### Если файл есть
Учти pin и Local deviations. Перед планом прочитай `$MA_HUB_ROOT/standards/` — особенно `02-product-preferences.md`, `03-engineering-defaults.md`, `01-role-and-voice.md`.

## Обязательный порядок (не пропускай шаги)

### 1. Пересказ идеи
- 2–4 предложения своими словами: что хочу получить и зачем
- Если идея пустая — попроси одно предложение и остановись

### 2. Уточнения (grill-me стиль)
Задай **не больше 3** вопросов простым языком. Для каждого:
- рекомендуемый вариант по умолчанию
- 2–4 готовых варианта на выбор (где уместно)

Спрашивай о самом важном: цель/результат, ограничения, что нельзя ломать, крайние случаи.
Если задача совсем простая и однозначная — можно сразу к плану с дефолтами (скажи, какие дефолты взял).

Используй навыки: `grill-me`; при продуктовых развилках — `office-hours` / `gstack`.

**Стоп:** дождись ответов (или явного «как рекомендуешь» / «дальше»).  
Пауза только ради этих бизнес-ответов — не ради «сначала сохранить черновик» и не ради технических коммитов.

### 3. План работ
После ответов напиши план:
- цель одним предложением
- шаги списком (бизнес-языком, без жаргона файлов/API)
- что будет готово / как проверить успех
- риски простыми словами
- что **не** делаем в этой итерации

Предложи режим выполнения:
- **safe** (по умолчанию) — после каждого крупного шага спрашиваешь
- **auto** — идёшь пакетами с чекпоинтами

### 4. Подтверждение
Спроси: «План ок? Пиши: **ок** / **ок auto** / правки».  
Это единственная обязательная пауза перед работой (бизнес-решение). Не дроби на «сначала запишем план в файл — ок?» отдельно от самого плана.

**До подтверждения код не пиши.**

### 5. После «ок»
- Запускай работу по плану
- В **auto** — доводи пакет до проверяемого результата, потом один чекпоинт; не останавливайся на каждом техническом сохранении
- В **safe** — пауза только на крупных шагах плана, не на «нужен ли commit»
- **Не** push / PR / prod из этого ритуала. На прод — только `/MA-deploy`.
- Перед финишем: сам проверь, что заявленное реально сделано (не отмечай готовым без доказательства)
- **Обязательно:** короткий `/code-review` **зоны фичи** (не всего продукта). Critical/High — сразу; Medium/Low — в список на решение. Не ждать фразы «сделай ревью».
- Bias простоты: прочитай skill **`ponytail`** с диска (пути — `$MA_HUB_ROOT/registry/external-skills.md`, пакет `dietrichgebert/ponytail`) и следуй ему; **не** копируй текст skill в план. Это **вкус** «не раздувать», не словарь «убери ИИ-стиль» и не автофикс деплоя.
- Если после фичи зона шумная (канцелярит, пересказ-комменты, пустые слои) — в итоге предложи `/MA-product-pass` по этой зоне. Не запускай полный прогон молча вместо идеи.

### 6. Итог и что дальше
Коротко: что сделано, как проверить. Предложи следующее по карте (не всё сразу):
- экран/UI ещё сырой → `/MA-design-screen`
- код шумный / много модулей → `/MA-product-pass`
- нужно на прод → `/MA-deploy`
- фича даёт новый пользовательский путь → предложить одну строку в блок обязательных путей визитки (эталон `$MA_HUB_ROOT/templates/release-must-work-paths.md`)

## Стиль ответа
- Русский, коротко, по делу
- Сначала вердикт/суть, потом детали
- На **каждой паузе и в итоге** — блок «Статус процесса» из `$MA_HUB_ROOT/standards/00-operating-model.md` (*Сейчас / Что происходит / Ждём / Обычно занимает / Что от вас*)
- После **завершённой** работы (не на шагах «жду ответ» / «жду ок») — блок «Следующие задачи» по правилу пользователя (ровно 4 пункта)
