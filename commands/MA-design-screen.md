# MA-design-screen

**Цель:** довести экран (админка / дашборд / лендинг / фронт) до проверяемого сильного UI — без кода до подтверждённого направления.

Я не дизайнер и не глубокий технарь: веди коротко, спрашивай по делу, технические детали решай сам.

**Вход:** $ARGUMENTS

Карта ритуалов: `$MA_HUB_ROOT/templates/ma-command-map.md`. **Это не чистка кода и не выкат.** Анти-ИИ словарь из полного прогона сюда не тащить — здесь вкус экрана (`04-design-defaults.md`).

## 0. Ворота: стандарт в проекте

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`.  
Проверь в **текущем проекте** файл `docs/MA-STANDARDS.md`.

### Если файла нет — стоп
Не начинай ритуал. Предложи создать визитку из `$MA_HUB_ROOT/templates/project-ma-link.md` → `docs/MA-STANDARDS.md`.

Объясни коротко **зачем**:
- это связь проекта с общими правилами Monster Automation (вкус, процесс, качество);
- без неё команда не знает pin / локальные отклонения и легко уйдёт «в общий шаблон», а не в закон этого продукта;
- сами правила живут в хабе (`standards/`), в проекте — только ссылка и ваши исключения.

Спроси: «Создать `docs/MA-STANDARDS.md`? **ок** / позже».  
До «ок» (или явного «позже, всё равно продолжай») дальше не иди. После создания — учти pin и Local deviations.

### Если файл есть
Учти pin и Local deviations. Перед направлением прочитай:
- `$MA_HUB_ROOT/standards/02-product-preferences.md`
- `$MA_HUB_ROOT/standards/04-design-defaults.md`

**Компас по умолчанию** (из стандарта): Vercel × Linear + удобство Apple HIG. Назови вслух. Другой эстетический мир — только по явной просьбе.

## Порядок

### 1. Тип поверхности
Один register вслух: **tool/admin/dashboard** или **marketing/brand/landing**. Если неясно — один вопрос с 2 вариантами.

### 2. Контекст (макс. 3 вопроса)
Цель экрана, светлая/тёмная/бренд, что нельзя ломать. Дефолты предложи сам. Жди ответ или «как рекомендуешь».

### 3. Направление
Коротко: компас, визуальное направление (1 абзац), что главное на первом экране, ключевые паттерны, 2–3 намеренных motion.

Навыки по ситуации (читай с диска, не копируй текст):
- admin/dashboard → `ui-ux-pro-max` + `shadcn`
- marketing → `design-taste-frontend` + `high-end-visual-design`
- любой UI → `impeccable`
- редизайн → `redesign-existing-projects`

**Стоп:** «Направление ок? **ок** / правки». Код до «ок» не пиши (кроме крошечного прототипа по просьбе).

### 4. Сборка и проверка
После «ок» — до проверяемого результата. Затем: `web-design-guidelines`; React/Next — `vercel-react-best-practices` / `nextjs-app-router-patterns`; при необходимости — `impeccable` polish.  
**Проверка экрана:** `verification-before-completion`; критичные клики через `agent-browser` (если браузера нет — явно в итоге, не притворяться что кликнули). Краткий итог: что сделано и как глянуть.

### 5. Что дальше
Не подменять деплоем и не запускать полный прогон «заодно». Предложи по карте:
- код после сборки шумный → `/MA-product-pass` по зоне экрана
- экран готов к проду → `/MA-deploy`
- новый пользовательский путь → предложить одну строку в блок обязательных путей визитки (эталон `$MA_HUB_ROOT/templates/release-must-work-paths.md`)

## Нельзя
- Начинать ритуал без решения по `docs/MA-STANDARDS.md` (создать / «позже»)
- Код до подтверждения направления
- Ломать компас и anti-slop из стандарта без явной просьбы
- Один экран ≠ одна главная работа
- Push / PR / prod из этого ритуала

## Стиль
- Русский, просто, короткие шаги
- На паузах и в итоге — «Статус процесса» из `$MA_HUB_ROOT/standards/00-operating-model.md` (*Сейчас / Что происходит / Ждём / Обычно занимает / Что от вас*)
- После **завершённой** сборки (не на «направление ок?») — блок «Следующие задачи» (ровно 4 пункта с копируемыми промптами)
