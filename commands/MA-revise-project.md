# /MA-revise-project

Подтянуть **текущий проект** к актуальным стандартам из публичного **ma-hub**.

Вы — консультант/БА. Ассистент — senior, который аудирует и предлагает план апгрейда без лишнего жаргона.

## Источник истины

Сначала найди корень **ma-hub**:
1. `~/.config/ma-hub/config` → `MA_HUB_ROOT`
2. иначе `~/ma-hub`, если есть `standards/`
3. иначе остановиться: попросить bootstrap (`git clone` публичного ma-hub + `./bootstrap/bootstrap.sh`)

Перед аудитом желательно обновить хаб до latest `main`:
`ma-hub-pull` или `$MA_HUB_ROOT/bootstrap/pull.sh`  
(если в `AGENTS.md` проекта указан **Pin** — уважать pin / `MA_HUB_REF`).

### Skills с хаба (обязательно при revise)

Список skills **не** копируется в продукт — он общий, из ma-hub. После обновления хаба машина должна иметь актуальный кэш:

1. MA-owned: `$MA_HUB_ROOT/bootstrap/install-skills.sh` (или уже через `ma-hub-ensure-latest` / `ma-hub-pull`)
2. Внешние по registry: `$MA_HUB_ROOT/bootstrap/install-external-skills.sh` — если менялся `registry/external-skills.*` или локально нет skills, на которые ссылаются `/MA-*` (см. `$MA_HUB_ROOT/registry/external-skills.md`)

В отчёте revise — короткий блок **«Skills на машине»**: актуально / нужно обновить (что именно). Пробелы — в план **первым пакетом** вместе с канон-файлами (или сразу предложить прогнать установку).  
**Не** создавать в проекте отдельный файл/таблицу «наши skills».

Читать **целиком** (или суммировать ключевые требования):

`$MA_HUB_ROOT/standards/`

Файлы:
- `VERSION`
- `00-operating-model.md`
- `01-role-and-voice.md`
- `02-product-preferences.md`
- `03-engineering-defaults.md`
- `04-design-defaults.md`
- `05-release-and-quality.md`

## 0. Ворота: канон-файлы

Убедись, что workspace — **конкретный продукт** (не home). Если открыт **сам ma-hub**, а цель — другой продукт: спроси путь и `move_agent_to_root` до правок. Сверка **хаба как репозитория команд** — только если пользователь явно сказал править ma-hub.

Следуй `$MA_HUB_ROOT/templates/project-canonical-pack.md`.

### Если пакета нет
Это **главный пробел**, не мягкий пропуск. В плане апгрейда — **первым пунктом**: создать **тройку** из эталонов `project-readme.md`, `project-agents.md`, `project-design.md` (все обязательные разделы, не пустые заголовки) **вместе с блоком обязательных путей релиза** в `AGENTS.md` (черновик 5–10 путей в плане, не молча). Есть старый `docs/MA-STANDARDS.md` — перенос в `AGENTS.md` и удаление. Есть `UI_UX_GUIDELINES.md` / `docs/design-system.md` — уникальное в `DESIGN.md` в **том же** пункте, не следующей задачей; исходник удалить (не указатель).

`llms.txt` в этом пакете **не сочинять**. Сначала найти, нет ли уже роута/генератора. В плане сразу следующий шаг: `/MA-seo-geo-audit` (среда local/prod) — он собирает карту для внешних ИИ (файл **или** генератор). Нет ни файла, ни роута, или заглушка — пробел GEO, не «потом когда-нибудь».

Объясни коротко **зачем** (в отчёте и при предложении плана):
- README — людям: суть, не путать с чем, кто пользуется, запуск;
- AGENTS.md — закон агента в репо (команды, запреты, хаб, pin, пути релиза);
- DESIGN.md — вид этого продукта и продуктовый чеклист UI, без копирования стандарта хаба и без пятого файла;
- llms.txt — карта для ChatGPT/Perplexity и т.п.; пишет только SEO+GEO-аудит (файл или уже существующий роут).

Аудит хаба всё равно начинай. Создание файлов — после «ок» на план (как и остальные правки), если пользователь не сказал создать сразу.

### Если пакет есть
Прочитай `AGENTS.md` (версия, policy, Local deviations, обязательные пути) и `DESIGN.md`. Сравни версию с `$MA_HUB_ROOT/standards/VERSION`. Сверь README/AGENTS/DESIGN с обязательными разделами эталонов (дыры — пробел). `llms.txt`: нет файла **и** нет роута / заглушка / не совпадает с P0 → **не править в сверке**, в план поставить `/MA-seo-geo-audit`. Затем **найди дубли стандартов и продуктовые UI-гайды** (см. ниже) — до массовых правок UI. Автоблок вроде `nextjs-agent-rules` в `AGENTS.md` не сносить.

## Один пакет канон-файлов, без копий правил

В продукте связь со стандартами — **тройка** (`README.md`, `AGENTS.md`, `DESIGN.md`) плюс `llms.txt` после `/MA-seo-geo-audit`.  
Сами правила живут только в ma-hub (`standards/`). **Не копировать** папку `standards/` и не плодить вторые «MA rules» в проекте.

### Что искать (кандидаты на дубль)

Искать по именам и смыслу, например:
- `*STANDARD*`, `*MA-*`, `docs/*standard*`, `docs/*ma*`
- `UI_UX_GUIDELINES.md`, `docs/design-system.md`, похожие продуктовые UI-чеклисты (уникальное → `DESIGN.md`, файл удалить в том же пакете)
- длинные копии operating / design / engineering / release правил из хаба
- Cursor rules / docs, которые повторяют процесс MA (роль, голос, релиз-чеклист хаба)

**Не трогать** чисто продуктовое: бренд, домен, доступы, ниша — если это не копия хаба. При сомнении → в отчёт как «не трогать», не удалять.

### Что делать с каждым кандидатом

Для каждого файла в отчёте предложить одно действие:

| Действие | Когда |
|----------|--------|
| **Перенести → удалить** | Дефолт. Файл дублирует стандарты MA **или** продуктовый UI-чеклист, который уже в `DESIGN.md` / `AGENTS.md`. Сначала **заменить все живые ссылки** на канон (поиск по имени файла по репо), затем удалить. **Не** оставлять stub «см. DESIGN.md», если на старый путь ссылается только `_archive/` |
| **Перенести → оставить путь** | Исключение: скрипт, CI, генератор или внешний инструмент **требует** этот путь. Тогда одна строка-указатель, не «на всякий случай» |
| **Не трогать** | Чистый продукт / бренд / домен без дубля хаба. Архив `legacy/` — замороженная история, имена старых файлов можно не переписывать |

Уникальное и нужное (отклонения, pin, локальные договорённости, **обязательные пути релиза**) → **в `AGENTS.md`**.  
Продуктовый вид и чеклист UI → **в `DESIGN.md`**.  
Дублирующий текст → убрать.  
Автоблок в начале `AGENTS.md` (`nextjs-agent-rules` и т.п.) → не удалять.

### Удаление — только после «ок»

**Всегда safe по умолчанию:** сначала список «удалить / оставить путь / не трогать», правки файлов — только после явного согласия пользователя. Не удалять молча.  
После «ок» на план — сделай **весь согласованный пакет** правок подряд (сначала доведи, потом один итог). Не останавливайся после каждого файла с вопросом «этот файл ок?», если он уже был в утверждённом списке.  
В том же пакете: поиск по имени каждого поглощённого файла → заменить живые ссылки на канон → удалить исходник. Не оставлять битые ссылки «на потом».

## Уточнить (≤3, с дефолтами)

1. **Глубина**  
   Рекомендую: **аудит + план + согласование, потом правки**.  
   Варианты: только отчёт / отчёт+правки safe / отчёт+правки auto.

2. **Объём**  
   Рекомендую: **продукт + дизайн + инженерия + релиз-чеклист + дедуп файлов стандартов**.  
   Варианты: только UI / только безопасность и доступ / всё.

3. **Нельзя ломать**  
   Рекомендую: **текущий прод-поток и бренд проекта сохраняем; стандарты — поверх; продуктовые правила не сносим**.  
   Попросите назвать святое.

Если ответов нет — брать дефолты и озвучить.

## Аудит (обязательный отчёт)

**Сначала** блок «Статус процесса» (`$MA_HUB_ROOT/standards/00-operating-model.md`):

| Поле | Значение |
|------|----------|
| Сейчас | нужно ваше решение / идёт процесс / готово |
| Что происходит | … |
| Ждём | ничего / ваш «ок» на план / … |
| Обычно занимает | — / пока не ответите |
| Что от вас | ничего / ответить на уточнения / «ок» на план · правки |

До «ок» на план: **нужно ваше решение**.  
После выполнения пакета: **готово** (или снова **нужно ваше решение**, если следующий пакет ждёт согласия).

Структура отчёта на русском, деловым языком:

### Вердикт
Одна фраза: насколько проект отстаёт от стандартов vX.Y.Z.

### Skills на машине
Кэш MA + внешних skills из registry: актуален / устарел / чего не хватает. Действие: ничего / `ma-hub-ensure-latest` / `install-external-skills.sh`.  
Не предлагать вести список skills внутри репозитория продукта.

### Канон-файлы
`README.md` / `AGENTS.md` / `DESIGN.md`: есть / каких **разделов** не хватает (эталоны `templates/project-*.md`). Есть ли отдельный UI-чеклист вне `DESIGN.md` → перенести в том же пакете **и заменить живые ссылки** на старое имя. `llms.txt`: живой файл **или** роут / нет / заглушка → нужен `/MA-seo-geo-audit` (не плодить `public/llms.txt`, если уже есть роут). Старый `docs/MA-STANDARDS.md`: перенести, заменить ссылки, **удалить** / нет.

### Соответствует
Что уже хорошо (короткий список).

### Пробелы (приоритет)
- Область (дашборд / канбан / auth / дизайн / инженерия / релиз)
- Что не так по стандарту
- Риск для бизнеса
- Предлагаемое действие
- Effort: S / M / L

### Дубли стандартов в проекте
Таблица или список:
- путь файла
- что внутри (кратко)
- действие: удалить / оставить путь (только если его требуют) / не трогать
- что перенести в `AGENTS.md` / `DESIGN.md`

### Локальные отклонения
Где проект **осознанно** другой (бренд, ниша) — не ломать, зафиксировать в `AGENTS.md` (Local deviations) и при нужде в `DESIGN.md`.

### Обязательные пути релиза
Сверить блок `## Обязательные пути релиза` в `AGENTS.md` с эталоном `$MA_HUB_ROOT/templates/release-must-work-paths.md`.
- Нет заголовка / пустая таблица / меньше 2 строк `always` / только заглушки `…` → **пробел**, не «потом».
- В плане показать черновик 5–10 путей этого продукта (путь / always или if-touched / область / роль). **Не** записывать молча.
- После «ок» на первый пакет — вписать в `AGENTS.md`. Не плодить отдельный файл каталога.

### Ритуалы (актуальный стандарт)
Соответствует карте `templates/ma-command-map.md` и релизу 2.0+: выкат одной волны / обязательные пути в `AGENTS.md` / канон-файлы / чистка отдельно / или пробел (что поправить в `AGENTS.md`).

### Git-хуки и CI vs `/MA-deploy` (скорость релиза + минуты Actions) — все проекты
Сверить husky / lefthook / pre-commit с `$MA_HUB_ROOT/templates/git-hooks-ma-deploy.md` (**жёсткий gate** в `/MA-deploy` Phase 0):
- pre-commit гоняет полный `pnpm test` / vitest без `MA_ATOMIC_PACKING=1`? → **блокер** (в auto чинит `/MA-deploy`, в safe ждёт «чини»)

Сверить `.github/workflows/` с `$MA_HUB_ROOT/templates/ci-ma-deploy.md` (**тот же gate**):
- job’ы кроме typecheck/test → блокер «толще шаблона»
- два+ job’а typecheck/test с повторным install → блокер «дороже эталона» (склеить в один)
- `push` + `pull_request` на `main`/`dev` без Local deviation «форки» → блокер «дубль событий»
- нет concurrency cancel-in-progress → замечание (в auto — добавить)

- Отдельный revise только ради хуков/CI **не обязателен**, если следующий шаг — `/MA-deploy auto`
- **Не** предлагать ослабить thin-состав или убрать локальный build — экономим форму (job’ы × события), не покрытие

### Клиентский Telegram после прода — продукты с внешними заказчиками
Сверить с `$MA_HUB_ROOT/templates/telegram-customer-update-ma-deploy.md` (+ snippet `templates/env-customer-telegram.snippet`):
- в `.env.example` есть `COMPANY_TELEGRAM_CHAT_ID`, `COMPANY_TELEGRAM_THREAD_ID_UPDATES` (без секретов)
- в `.env.local` заполнены `COMPANY_*` для топика **Updates** (не ops-алерты)
- общий бот: `MA_TELEGRAM_BOT_TOKEN` в `~/.config/ma-hub/telegram.env` на машине (не в git продукта)
- формат апдейтов — **единый** Slack/GitHub тон (строка сути сразу под заголовком; What's New / Improvements / Fixes); полное полезное покрытие (не «топ-6»); Local deviations только язык/чат, не другая структура
- нет chat id при revise — замечание: при выборе «да, уведомить клиента» `/MA-deploy` Phase 7.5 попросит добавить ключи; при «нет (только техника)» ключи не требуются

### Тестовые входы для обязательных путей — все продукты
Сверить с `$MA_HUB_ROOT/templates/env-qa-test-accounts.snippet` + канон в `templates/release-must-work-paths.md`:
- в `.env.example` — ключи и канон **email**, пароль **пустой** (git)
- в `.env.local` — канон email **и** пароль; если пусто или другое — агент **сам дописывает** из канона (не спрашивать)
- паролей нет в `AGENTS.md`, чате, отчёте
- на проде есть пользователи manager и client с канон-email; нет → **предложить** создать + демо-данные (не молча)
- учётки только демо: без боевых денег и чужих данных

### Ритуалы vs актуальный стандарт (все проекты)
Сверить `AGENTS.md` и привычки репо с `$MA_HUB_ROOT/standards/05-release-and-quality.md` + `templates/ma-command-map.md` (стандарт **v2.0+**):
- Выкат — `/MA-deploy` с **одним ревью выбранной волны** (не куски; не весь грязный ком; смесь зон — несколько выкатов; чужие правки не блокеры)
- В `AGENTS.md` — блок обязательных путей релиза (эталон `templates/release-must-work-paths.md`); без него выкат не стартует
- Канон-файлы: тройка с заполненными разделами; UI-чеклист продукта — в `DESIGN.md`, не пятый файл; живые ссылки на поглощённые файлы заменены; `llms.txt` — после `/MA-seo-geo-audit` (файл или роут), не из головы; старый `docs/MA-STANDARDS.md` — перенести и удалить
- Тестовые входы — канон хаба в `.env.local`; нет ролей на проде → предложить создать + демо
- Глубокая чистка — `/MA-product-pass` (**не** релиз; simplify «убери ИИ-стиль», не ponytail деплоя)
- Если `AGENTS.md`/доки всё ещё описывают старый релиз «одним комком» или смешивают чистку с выкатом → **пробел** в отчёте, пакет: обновить `AGENTS.md` / Local deviations, не переписывать продукт молча

### План подтягивания
Пошагово, пакетами. Safe = пауза после каждого пакета. Auto = чекпоинты без лишних вопросов.  
Первый пакет желательно: **тройка README/AGENTS/DESIGN + обязательные пути + вклейка существующего UI-чеклиста в DESIGN.md + замена живых ссылок на старые файлы + удаление исходников (не указатели) + QA в `.env.example`/`.env.local` + при отсутствии ролей на проде предложение создать + демо + дедуп** (после «ок»). Сразу в плане: **`/MA-seo-geo-audit` для `llms.txt`** (учесть роут, если уже есть). Потом UI/инженерия; хуки и CI — отдельный маленький пакет, если тяжёлые/дорогие.

## Исполнение

- До «ок» на план (в safe) — **не** массово переписывать UI и **не** удалять файлы.
- При правках: следовать standards + `shadcn` / `vercel-react-best-practices` / `supabase-postgres-best-practices`.
- Создать/обновить **тройку** из `$MA_HUB_ROOT/templates/project-canonical-pack.md` (эталоны readme/agents/design)  
  с заполненными обязательными разделами, актуальной версией, policy, отклонениями, блоком обязательных путей и тем, что перенесли из дублей / старой визитки / UI-чеклиста.  
  Автоблок `AGENTS.md` сверху не сносить. `llms.txt` не выдумывать — после «ок» на тройку предложить `/MA-seo-geo-audit` (если карта уже из роута — аудит обновляет генератор).
- После «ок» на дедуп: для каждого поглощённого файла — поиск по имени по репо, заменить живые ссылки на `DESIGN.md` / `AGENTS.md`, **затем удалить** (указатель — только если путь ещё требуют). Не оставлять stub «на архив» и не оставлять битые ссылки в handbook / rules / скриптах.
- Обновить строку в `$MA_HUB_ROOT/registry/projects.md` (если доступен хаб для записи).
- Не коммитить без просьбы.
- После **готово** по пакету — блок «Следующие задачи» (4 пункта). На паузе «ок на план» — не дублировать.
