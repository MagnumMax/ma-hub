# /MA-product-pass

Универсальный прогон продукта: план модулей → ревью → simplify → финальный проход.

Ты — старший инженер. Задача: разбить ВЕСЬ продукт на средние функциональные модули, пройти каждый отдельно (/code-review + /simplify), затем сделать общий финальный проход.

**Вход:** $ARGUMENTS

Отвечай на языке пользователя. Пиши понятно.

В паузах и в итогах длинного прогона сначала блок **«Статус процесса»** — *Сейчас / Что происходит / Что от вас* (см. `$MA_HUB_ROOT/standards/00-operating-model.md`).

## 0. Ворота: стандарт в проекте

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`.  
Если хаба нет — скажи запустить bootstrap и остановись.  
Проверь в **текущем проекте** `docs/MA-STANDARDS.md`. Нет файла — предложи создать визитку из `$MA_HUB_ROOT/templates/project-ma-link.md` (можно продолжать после «ок» / «позже, всё равно продолжай»). Учти pin и Local deviations, если визитка есть.

---

## Режим моделей (обязательно)

1. **Фаза A (анализ и план)** — через субагентов / Task на **самой высокой доступной модели** (gpt-*-high, grok-*-high, claude opus и т.п.). Не планируй «на глаз» слабой моделью, если высокие доступны.
2. **Фаза B и C (исполнение)** — обычный чат / **Auto**: правки, проверки, /code-review, /simplify.
3. Если высокая модель недоступна (лимит API и т.п.) — явно скажи, сделай план лучшей доступной и продолжай Фазу B.

---

## Уточнения перед стартом (макс. 3)

Если пользователь ещё не ответил — спроси, с дефолтом и вариантами:

1. Scope прогона: весь продукт / только текущий diff / конкретная зона?
   - Дефолт: весь продукт.
2. Размер модуля: средний (~1–3 дня ревью) / мельче / крупнее?
   - Дефолт: средний.
3. Лимит за сессию: все модули / только первые N (остальное — продолжение позже)?
   - Дефолт: все модули; финальную Фазу C запускай только когда весь план закрыт.

Если ответы уже есть в `$ARGUMENTS` или это продолжение — не переспрашивай.  
Дополнительно всегда действует: после /code-review **сразу чинить Critical и High**; Medium/Low — в отчёте, править только если дёшево и внутри зоны модуля.

## Фаза A — карта продукта и план (высокая модель)

1. Исследуй репозиторий параллельно высокими моделями:
   - маршруты / экраны;
   - доменные lib / services / schema;
   - docs, ADR, README, glossary — если есть;
   - API / workers / cron / webhooks;
   - auth, billing, фон — как отдельные контуры.
2. Собери **пошаговый план** средних модулей (не атомарные экраны и не «весь монолит»).
3. Порядок: фундамент (доступ/идентичность) → пользовательские зоны → админ/операции → дизайн/контент → фон/инфра/публичка.
4. Для **каждого** модуля — только такой формат (без «Цели» и «Ожидаемого результата»):

### Модуль NN — <короткое бизнес-имя>
**Scope (зона):** что это за контур простыми словами; 2–6 стартовых якорей (папки/документы), откуда начинать; связанные файлы *внутри того же домена* можно включать по импортам/тестам/guards. Явно: какие соседние модули плана **не** трогать.
**План:**
1. /code-review по зоне модуля
2. Сразу исправить все находки Critical и High
3. Medium/Low — зафиксировать; править только точечно, если просто и в зоне
4. /simplify по той же зоне (без расширения на другие модули)
5. Краткий итог: что исправлено / что отложено

### Правила Scope (критично)

- Scope — **ориентир зоны**, не жёсткий allowlist файлов.
- Агент **может** заходить в связанные файлы того же домена (actions, тесты, layout-guards, schema helpers), если находка или упрощение без этого неполны.
- Агент **не может** уезжать в другие модули плана «заодно».
- Не раздувай зону до половины продукта: если тянет на соседний крупный контур — это отдельный модуль плана.

5. Выведи таблицу порядка: NN | модуль | зачем такой порядок.
6. **Покажи план и остановись** до явного «ок / начинай / go».  
   Исключение: пользователь сразу написал «сразу выполняй» / «full run без паузы».

## Фаза B — исполнение по модулям (Auto)

Иди по плану, модуль за модулем. Один модуль = полный цикл, затем следующий.

### B1. /code-review (+ фиксы Critical/High)
- Ревью в зоне модуля (мягкий Scope выше).
- Приоритет: баги → регрессии поведения → безопасность → пробелы в тестах.
- Findings — основа ответа, по серьёзности.
- **Сразу исправляй Critical и High.**
- Не рефакторь соседние модули.
- После фиксов — лёгкие проверки по затронутому (тесты/линт по возможности).

### B2. /simplify (та же зона)
- Как /simplify: параллельные read-only субагенты (качество / perf / reuse), затем точечные упрощения самому.
- Поведение сохранить. Крупный рефактор без нужды — в «отложено».
- Не трогай несвязанные локальные изменения пользователя.
- Не расширяй упрощения на другие модули плана.

### B3. Итог модуля
Коротко: Critical/High закрыты? Что упростили? Что на финал/бэклог?

Если задан лимит N — после N-го модуля остановись, выдай итог и готовый промпт «продолжить с модуля N+1». Фазу C не запускай, пока план не закрыт целиком.

---

## Фаза C — общий проход после ВСЕХ модулей

1. **Общий /code-review** по продукту (или всем зонам плана): стыки модулей, регрессии после серии фиксов, безопасность на границах, сквозные тесты.
2. Снова **сразу починить Critical и High**.
3. **Общий /simplify** по накопленному diff / затронутым зонам (не расползаться по нетронутому легаси без причины).
4. Финальный отчёт:
   - модули и статусы;
   - оставшиеся Medium/Low / отложенное;
   - риски;
   - что проверить руками.

## Правила качества (везде)

- Не коммить и не пушь, пока пользователь не попросил.
- Секреты, .env, ключи — не трогать и не коммитить.
- Деньги: не float; минимальные единицы валюты, если тема про деньги.
- Соблюдай AGENTS.md / архитектурные запреты проекта, если есть.
- Не выдумывай зоны: опирайся на реальные пути и домен репозитория.
- Имена сущностей — канон проекта (glossary), без синонимов.
- В конце значимого ответа — блок «Следующие задачи» (4 пункта с копируемыми промптами), **только если** это принято в правилах пользователя; иначе пропусти.

## Старт

1. Уточнения (если нужны) или дефолты выше.

3. План: таблица порядка + блоки **Модуль / Scope (зона) / План**.
4. После подтверждения — Фаза B по всем модулям (или первым N), затем Фаза C когда план закрыт.
