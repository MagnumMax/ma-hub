# /MA-product-pass

Универсальный **глубокий прогон** продукта: план модулей → ревью → simplify → финальный проход.  
Это **не** релиз и **не** замена `/MA-deploy`.

**Вход:** $ARGUMENTS

Отвечай на языке пользователя. Пиши понятно.

В паузах и в итогах длинного прогона сначала блок **«Статус процесса»** — *Сейчас / Что происходит / Ждём / Обычно занимает / Что от вас* (см. `$MA_HUB_ROOT/standards/00-operating-model.md`).

## Роль vs `/MA-deploy` (закон)

| | `/MA-product-pass` | `/MA-deploy` |
|---|-------------------|--------------|
| Зачем | Глубокая чистка и качество по модулям | Выкат на прод |
| Нарезка | Модули продукта (фаза A) | Одна волна (тема) целиком |
| После review | **`/simplify`** (эталон ниже) | **ponytail с автофиксом** |
| Commit / push / CI / prod | **Нет**, пока пользователь не попросил | Да, по пайплайну деплоя |

- **Не** подменять simplify на ponytail и **не** запускать деплой «заодно».
- После закрытого product-pass выкат — отдельной командой `/MA-deploy`.
- Эталон simplify: `$MA_HUB_ROOT/templates/simplify-ma-product-pass.md`.
- Карта ритуалов: `$MA_HUB_ROOT/templates/ma-command-map.md`.

После закрытого прогона (не на паузе плана): выкат — `/MA-deploy`; сырой экран — `/MA-design-screen`; следующая фича — `/MA-idea-to-plan`.

## 0. Ворота: канон-файлы

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`.  
Если хаба нет — скажи запустить bootstrap и остановись.  
Следуй `$MA_HUB_ROOT/templates/project-canonical-pack.md` (раздел «Ворота /MA-*»). Нет пакета — предложи создать (можно продолжать после «ок» / «позже, всё равно продолжай»). Учти pin и Local deviations из `AGENTS.md`, если файл есть.

## Режим моделей (обязательно)

1. **Фаза A (анализ и план)** — через субагентов / Task на **самой высокой доступной модели** (gpt-*-high, grok-*-high, claude opus и т.п.). Не планируй «на глаз» слабой моделью, если высокие доступны.
2. **Фаза B и C (исполнение)** — обычный чат / **Auto**: правки, проверки, /code-review, /simplify по эталону.
3. Если высокая модель недоступна (лимит API и т.п.) — явно скажи, сделай план лучшей доступной и продолжай Фазу B.

## Уточнения перед стартом (макс. 3)

Если пользователь ещё не ответил — спроси, с дефолтом и вариантами:

1. Scope прогона: весь продукт / только текущий diff / конкретная зона?
   - Дефолт: весь продукт. Если diff/зона — план модулей **только** в этих границах (не раздувать до «всего репо»).
2. Размер модуля: средний (~1–3 дня ревью) / мельче / крупнее?
   - Дефолт: средний.
3. Лимит за сессию: все модули / только первые N (остальное — продолжение позже)?
   - Дефолт: все модули; финальную Фазу C запускай только когда весь план закрыт.

Если ответы уже есть в `$ARGUMENTS` или это продолжение — не переспрашивай.

**Всегда действует:**
- после /code-review **сразу чинить Critical и High**;
- Medium/Low и спорное simplify → **сводный backlog** (таблица ниже); точечно чинить только дешёвое внутри зоны;
- после B1 (или сразу, если Critical/High не нашлись) — **всегда** полноценный simplify по эталону (**убери ИИ-стиль**). Шум и локальные имена — сразу; ломка URL/БД/публичного API — в backlog. Нельзя пропускать «потому что правок мало».

### Сводный backlog (формат как в деплое)

Копить по модулям, в паузах и в финале показывать одну таблицу:

| # | Модуль | Проблема | Серьёзность | Рекомендация |
|---|--------|----------|-------------|--------------|
| … | NN | … | Med/Low / спорное | чинить / не чинить / отложить |

Пауза на решения — когда список мешает идти дальше или пользователь просил решать пакетно. Иначе копить до отчёта модуля / лимита N / финала.

## Фаза A — карта продукта и план (высокая модель)

1. Исследуй репозиторий параллельно высокими моделями:
   - маршруты / экраны;
   - доменные lib / services / schema;
   - docs, ADR, README, glossary — если есть;
   - API / workers / cron / webhooks;
   - auth, billing, фон — как отдельные контуры.
2. Собери **пошаговый план** средних модулей (не атомарные экраны и не «весь монолит»). При scope=diff/зона — только модули, пересекающие этот scope.
3. Порядок: фундамент (доступ/идентичность) → пользовательские зоны → админ/операции → дизайн/контент → фон/инфра/публичка.
4. Для **каждого** модуля — только такой формат (без «Цели» и «Ожидаемого результата»):

### Модуль NN — <короткое бизнес-имя>
**Scope (зона):** что это за контур простыми словами; 2–6 стартовых якорей (папки/документы), откуда начинать; связанные файлы *внутри того же домена* можно включать по импортам/тестам/guards. Явно: какие соседние модули плана **не** трогать.
**План:**
1. /code-review по зоне модуля
2. Сразу исправить все находки Critical и High
3. Medium/Low — в backlog; править только точечно, если просто и в зоне
4. **Обязательно:** полноценный /simplify по эталону (убери ИИ-стиль; сжать на месте; контракты — в backlog)
5. Лёгкие проверки по зоне (если дёшево) + **отчёт по модулю**

### Правила Scope (критично)

- Scope — **ориентир зоны**, не жёсткий allowlist файлов.
- Агент **может** заходить в связанные файлы того же домена (actions, тесты, layout-guards, schema helpers), если находка или упрощение без этого неполны.
- Агент **не может** уезжать в другие модули плана «заодно».
- Не раздувай зону до половины продукта: если тянет на соседний крупный контур — это отдельный модуль плана.

5. Выведи таблицу порядка: NN | модуль | зачем такой порядок.
6. **Покажи план и остановись** до явного «ок / начинай / go».  
   Исключение: пользователь сразу написал «сразу выполняй» / «full run без паузы».

## Фаза B — исполнение по модулям (Auto)

Иди по плану, модуль за модулем. Один модуль = полный цикл, затем следующий.  
**Порядок внутри модуля жёсткий:** B1 → B2 → B3. Переходить к следующему модулю **только после** полноценного simplify и отчёта по текущему.

### B1. /code-review (+ фиксы Critical/High)
- Ревью в зоне модуля (мягкий Scope выше).
- Приоритет: баги → регрессии поведения → безопасность → пробелы в тестах.
- Findings — основа ответа, по серьёзности.
- **Сразу исправляй Critical и High.**
- Не рефакторь соседние модули.
- После фиксов — лёгкие проверки по затронутому (тесты/линт по возможности).

### B2. /simplify — обязательно, полноценно (та же зона)
- Эталон: `$MA_HUB_ROOT/templates/simplify-ma-product-pass.md` (прочитать с диска целиком).
- Мантра: **убери ИИ-стиль**. Цель — чтобы следующий человек читал код по именам, не по комментариям-пересказу.
- Жёстко на **шум**: пересказ, мёртвое, одноразовые обёртки, канцелярит внутри зоны, копипаста. Сжимать **на месте**, не плодить новые файлы «для порядка».
- Не молча: URL, колонки БД, ключи переводов, публичный API наружу зоны, проверки входа/ролей/денег/RLS.
- Порядок: сначала срезать шум → имена по glossary → инлайн → типы/React. Не изобретать слой, который только что инлайнил.
- Запускай **всегда** после B1. Не ponytail вместо simplify. ИИ-шум не откладывать «на вкус».
- Не трогай несвязанные локальные изменения пользователя. Не уезжай в другие модули плана.

### B3. Отчёт по модулю (обязателен)
После B2 выдай отчёт в таком виде:

#### Отчёт — Модуль NN — <имя>
- **Critical/High:** найдены / исправлены / не найдены
- **Medium/Low:** backlog (что добавлено; что поправлено точечно)
- **Simplify:** что упростили; что просмотрели, но не трогали; что в backlog
- **Анти-ИИ:** пункты словаря 1–12 (сработали / не нашли); **2–3 «было → стало»** простым языком; что ушло в backlog как контракт (URL/БД/API)
- **Проверки:** что прогнали (тесты/линт) и результат
- **Риски / руками:** что стоит глянуть человеку
- **Статус модуля:** закрыт / закрыт с оговорками

Если задан лимит N — после N-го модуля остановись, выдай **сводный отчёт по пройденным** + таблицу backlog + готовый промпт «продолжить с модуля N+1». Фазу C не запускай, пока план не закрыт целиком.

## Фаза C — общий проход после ВСЕХ модулей

1. **Общий /code-review** по продукту (или всем зонам плана): стыки модулей, регрессии после серии фиксов, безопасность на границах, сквозные тесты.
2. Снова **сразу починить Critical и High**.
3. **Узкий simplify (C3)** по эталону — только стыки + накопленный diff прогона. **Не** повторять полный B2 по каждому уже закрытому модулю. Подробности: `templates/simplify-ma-product-pass.md` § «Узкий C3».
4. **Проверки целостности:** один разумный прогон по проекту (typecheck и/или test из `package.json`, что есть и не разорительно). Fail → починить или явно в риски/блокер отчёта. Это **не** замена `/MA-deploy`.
5. **Финальный отчёт** (обязателен, в конце ответа):

#### Финальный отчёт — /MA-product-pass
- **Scope прогона:** весь продукт / diff / зона; размер модулей; лимит N если был
- **Модули:** таблица NN | имя | статус (закрыт / с оговорками) | Critical/High | simplify B2 сделан?
- **Исправлено:** кратко по Critical/High, значимым упрощениям и анти-ИИ (переименования / срез шума)
- **Backlog:** сводная таблица (чинить / не чинить / отложить) — все открытые пункты
- **Проверки C:** typecheck/test — результат
- **Риски:** что может всплыть
- **Проверить руками:** чеклист
- **Дальше:** выкат только через `/MA-deploy` (если нужен прод); карта — `templates/ma-command-map.md`
- **Итог:** готовность продукта после прогона (одной фразой)

## Правила качества (везде)

- Не коммить и не пушь, пока пользователь не попросил.
- Секреты, .env, ключи — не трогать и не коммитить.
- Деньги: не float; минимальные единицы валюты, если тема про деньги.
- Соблюдай `AGENTS.md` / `DESIGN.md` / архитектурные запреты проекта.
- Не выдумывай зоны: опирайся на реальные пути и домен репозитория.
- Имена сущностей — канон проекта (glossary), без синонимов.
- **Нельзя** завершать модуль или Фазу C без полноценного simplify (B2 / узкий C3) и отчёта.
- **Нельзя** подменять product-pass деплоем или ponytail-ритуалом релиза.
- В конце значимого ответа — блок **«Следующие задачи»** (4 пункта с копируемыми промптами), по правилам пользователя.

4. Обязательно: полноценный /simplify по эталону (убери ИИ-стиль; без расширения)

## Старт

1. Уточнения (если нужны) или дефолты выше.
2. Фаза A на высоких моделях.
3. План: таблица порядка + блоки **Модуль / Scope (зона) / План**.
4. После подтверждения — Фаза B по всем модулям (или первым N), затем Фаза C когда план закрыт.
5. Любой завершённый цикл (модуль / лимит N / Фаза C) заканчивается **отчётом** (+ backlog).
