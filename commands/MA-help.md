# MA-help — команды Monster Automation

Покажи этот список коротко и предложи, какую команду запустить. Все команды начинаются с **MA-** — в чате набери `/MA` и выбери нужную.

Карта «когда что / что дальше»: `$MA_HUB_ROOT/templates/ma-command-map.md` (прочитай и следуй).

## Hub (источник правды)

Сначала найди корень **ma-hub**:
1. `~/.config/ma-hub/config` → `MA_HUB_ROOT`
2. иначе `~/ma-hub`, если есть `standards/`
3. иначе скажи запустить bootstrap: `git clone … && ./bootstrap/bootstrap.sh`

**Истина только в репозитории ma-hub** (`commands/`, `skills/`, `standards/`, `registry/`).  
`~/.cursor/commands/` и `~/.cursor/skills/` — кэш после `bootstrap` / `ma-hub-pull`.  
Внешние skills: ссылки в `registry/external-skills.md`, тела — с upstream через `install-external-skills.sh`.  
Стандарты: `$MA_HUB_ROOT/standards/` (VERSION в том файле).

## Когда что (одна фраза)

Идея или фича → `/MA-idea-to-plan`. Экран → `/MA-design-screen`. Сверка со стандартами → `/MA-revise-project`. Чистка кода / ИИ-шум → `/MA-product-pass`. На прод → `/MA-deploy`. Поиск и ответы ИИ → `/MA-seo-geo-audit`.

Типичный путь: сверка (если отстал) → идея и/или дизайн → при шумном коде полный прогон → выкат → SEO.

## Ритуалы

| Команда | Когда вызывать |
|---------|----------------|
| `/MA-idea-to-plan` | Сырая идея / фича → уточнения → план → работа (не выкат) |
| `/MA-design-screen` | Админка, дашборд, лендинг, красивый фронт (не чистка кода) |
| `/MA-revise-project` | Сверить проект со стандартами ma-hub и подтянуть (визитка + обязательные пути релиза) |
| `/MA-product-pass` | Глубокая чистка (не релиз): модули → review + simplify «убери ИИ-стиль»; выкат через `/MA-deploy` |

## Релиз

| Команда | Когда вызывать |
|---------|----------------|
| `/MA-deploy` | Полный цикл перед продом: сегментный review → ponytail по кускам (таблица net, иначе стоп) → правки → упаковка → push → CI → PR → prod → обязательные пути |

## Справка

| Команда | Когда вызывать |
|---------|----------------|
| `/MA-help` | Этот список |

**Во всех длинных `/MA-*`:** в паузе и в итоге сначала блок «Статус процесса» — *Сейчас / Что происходит / Ждём / Обычно занимает / Что от вас* (см. `standards/00-operating-model.md`). После **готово** — «Следующие задачи» (4 пункта), не на паузе «жду ответ».

**Ворота во всех ритуалах:** сначала проверка `docs/MA-STANDARDS.md` в проекте. Нет файла → предложить создать визитку и объяснить зачем (шаблон `templates/project-ma-link.md`). `/MA-revise-project` при отсутствии визитки ставит её создание **и блок обязательных путей** первым пунктом плана. `/MA-deploy` без списка путей не стартует: дописать в выкате или сначала сверка; полную сверку из выката не запускать.

**Три упрощения** (не смешивать) — в карте: идея = вкус ponytail; полный прогон = simplify «убери ИИ-стиль»; выкат = ponytail с автофиксом **и доказательством по кускам**.

## Как пользоваться
1. Открой чат в нужном проекте
2. Напиши `/MA` и выбери команду
3. После команды опиши задачу одним-двумя предложениями
4. На новом ноутбуке: bootstrap из публичного ma-hub (см. README хаба)

**Заметка:** security / UX / guidelines — через навыки бандла или обычным текстом в чате.

Если пользователь не указал задачу — спроси одну фразу: что делаем. Напомни, что стандарты, команды и MA-skills живут в ma-hub и обновляются через `ma-hub-pull` / weekly.
