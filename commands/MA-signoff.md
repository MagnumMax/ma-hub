# MA-signoff

**Цель:** в конце работы в этом чате ответить как сеньор (продукт + техника): задача закрыта сполна? сделана качественно? что ещё доделать?

Я не программист. Говори простым языком. **Не выкатывай на прод.** **Не чини**, пока не скажу «чини».

**Вход:** $ARGUMENTS (если пусто — возьми задачу из этого чата).

Карта ритуалов: `$MA_HUB_ROOT/templates/ma-command-map.md`.
Это **не** `/MA-deploy` и **не** `/MA-product-pass`. Ponytail и simplify здесь не гонять.

## 0. Ворота: канон-файлы

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`.
Если хаба нет — скажи запустить bootstrap и остановись.
Следуй `$MA_HUB_ROOT/templates/project-canonical-pack.md` (как `/MA-product-pass`: нет тройки — предложи создать, можно продолжать после «ок» / «позже»).

В паузах и в итоге сначала блок **«Статус процесса»**.

## Кого изображаешь

Один взгляд сразу с трёх сторон (не три отчёта):

- продукт: то, что просили, реально есть у человека;
- архитектура: решение уместное, без лишнего и без дыр;
- инженерия: сделано грамотно, без явных багов и сюрпризов.

## Порядок (не пропускай)

### 1. Что принимаем

Коротко (3–6 строк) перескажи исходную задачу: цель, ожидаемый результат, что сознательно не входило в работу.

Нет ясной задачи в чате и нет `$ARGUMENTS` — спроси одно предложение и остановись.

### 2. Сверка с фактами

Не верь самоотчёту чата. Проверь по делу:

- git: что реально изменилось (uncommitted + коммиты этой работы);
- экраны / поведение / тексты, которые обещали;
- если обещали проверку в браузере или тесты — было ли это сделано, не «потом».

Нет кода в дереве (только план, текст, решение) — оцени то, что есть; ботов по diff не выдумывай.

### 3. Ревью по типу темы (сам выбери, не спрашивай)

Один проход каждого нужного бота. **Не** вызывать меню `/review`. **Не** чинить findings в этом шаге.

- `/code-review` — всегда, если есть код этой задачи (зона задачи, не весь продукт).
- `review-bugbot` — если менялось поведение (логика, поток, API, данные). Не на правку только текстов.
- `review-security` — если тема про вход, роли, платежи, персональные данные, секреты.

Нет файла skill на диске — напиши, чего не хватает, и продолжи оценку без этого бота (не стоп всего ритуала).
Findings — короткой таблицей: серьёзность / где / суть. Critical и High не прятать.

### 4. Оценка 1–10

Одна цифра, не три шкалы.

Жёсткие потолки:

- задача по смыслу не закрыта (дыры относительно просьбы) → максимум **6**, даже если код аккуратный;
- есть Critical или High из ревью → максимум **7**;
- **8+** только если: просьба закрыта сполна, нет Critical/High, решение уместное, ничего важного не отложено «на потом».

**Готово** = оценка **≥ 8** и нет дыр по смыслу.
Иначе — не готово, даже если цифра красивая.

К оценке — 3–5 фраз: что сильно, что слабо, почему такая цифра.

### 5. Вердикт

Покажи:

- вердикт: готово / не готово;
- оценка: N/10;
- закрыто сполна: да / нет (и чего не хватает);
- боты: какие запустил и зачем;
- доделки: нумерованный список простым языком (сначала смысл и дыры, потом Critical/High, потом остальное).

Пустой список доделок — так и напиши.

Дальше одна фраза:

- не готово → «Пиши: **чини** / что делать из списка / хватит»;
- готово → «Можно выкатывать отдельно: `/MA-deploy`. Пиши: **чини** (если всё же поправить) / хватит».

**До «чини» код не правь.** Коммит, push, PR, прод из этого ритуала запрещены.

После «чини» — только пункты из согласованного списка, затем короткий повтор шагов 4–5 (без второго круга всех ботов, если код почти не менялся; если менялось поведение или доступ — нужный бот ещё раз, по одному).
