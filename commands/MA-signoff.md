# MA-signoff

**Цель:** принять **бизнес-задачу** этого чата, как старший продакт. Техническое ревью — в `/MA-deploy`, здесь его не делать.

Я не программист. Коротко, простым языком. **Не выкатывай. Не чини. Не запускай** `/code-review`, bugbot, security, ponytail, simplify.

**Вход:** $ARGUMENTS (если пусто — задача из этого чата).

Карта: `$MA_HUB_ROOT/templates/ma-command-map.md`.

## 0. Хаб

Найди **ma-hub**: `~/.config/ma-hub/config` → `MA_HUB_ROOT`, иначе `~/ma-hub`. Нет хаба — скажи bootstrap и стоп.  
Канон-файлы не пересказывать. Нет тройки — не стопать (как `/MA-product-pass`).

Статус процесса — **только в итоге**, одна короткая таблица. По пути молчи: без «сначала сверюсь», без git-отчёта.

## Порядок

### 1. Прочитай весь диалог

Исходная просьба + как она уточнялась (не только первое сообщение и не самоотчёт агента).

Сформулируй **одну** бизнес-задачу: для кого, какой результат в продукте. Что в этом чате сознательно отложили — одной фразой.

Нет ясной задачи — одно предложение «что принимаем?» и стоп.

### 2. Сверка по смыслу

Закрыт ли **продуктовый** результат (письма уходят / экран есть / человек может сделать X) — по обещаниям чата и тому, что реально показали.

Не разбирать код, коммиты, миграции, соседний грязный diff. Техническое «ещё не на проде» — не дыра задачи, если так и договорились.

### 3. Оценка 1–10 — только этот чат

Одна цифра: закрыли ли **то, что просили в этом чате**. Не код. Не «насколько тема исчерпана».

- просьба **этого чата** не закрыта → максимум **6**;
- **8+** если то, что просили здесь, у человека есть (или явно показали);
- **9–10** можно, даже если по большой теме ещё много срезов.

Список «ещё по теме» **не снижает** оценку. Сознательно отложенное в этом чате — тоже не штраф, если так договорились.

**Готово** = ≥ 8 и нет дыр относительно просьбы **этого чата**.

### 4. Отчёт (только это, без других разделов)

Держи **коротко**. Запрещено: таблицы ботов, пути файлов, git, канон, «какие проверки запускал».

Два разных смысла, не смешивать:

- **В этом чате** — дыры текущей просьбы (если есть). Они влияют на оценку.
- **Ещё по этой теме** — следующие **продуктовые** срезы большой задачи для клиента. Не влияют на оценку.

В список «ещё по теме» **нельзя:** выкат, миграции, коммиты, тесты, ревью, «отделить от другой работы», «ещё не на проде». Это выкат / техника, не продукт.

Только то, что человек получит в продукте (новые письма, другие шаги, экран, правило). Нет таких срезов — напиши «ничего».

```markdown
### Статус процесса
| Сейчас | готово |
| Что происходит | продакт-приёмка |
| Ждём | ваш ответ |
| Что от вас | «доделай» / что из списка / хватит |

**Задача:** 2–4 предложения — что ставили в этом чате (и как уточняли).

**Вердикт:** готово / не готово · **N/10**
**В этом чате:** закрыто / не закрыто — одна фраза; если не закрыто — 1–3 дыры этой просьбы.

**Ещё по этой теме:** 3–7 следующих срезов для клиента (или «ничего»). Не техника и не выкат.
```

Дальше одна строка: «Пиши: **доделай** / что из списка / **хватит**. На прод — отдельно `/MA-deploy`.»

**До «доделай» / «чини» ничего не правь.** После — только выбранные пункты, затем короткий повтор вердикта (без нового романа).
