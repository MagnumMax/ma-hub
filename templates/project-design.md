# DESIGN.md — эталон

Корень репо. **Как выглядит и ощущается этот продукт.** Компас и anti-slop — в хабе `standards/04-design-defaults.md`. Сюда **не копировать** тот файл — только решения **этого** продукта.

Нет экранов пока: всё равно завести файл и заполнить Compass + «UI ещё нет» в Surface. Иначе агент выдумает вкус.

Пустой раздел запрещён: либо решение продукта, либо «не применимо: …».

## Обязательные разделы

| Раздел | Что должно быть |
|--------|-----------------|
| **Compass** | Одна строка: Vercel × Linear + Apple HIG **или** явное исключение (бренд) |
| **Surface** | tool / admin / dashboard **или** marketing / landing; если экранов нет — так и написать |
| **Tokens** | Цвет акцента, фон, шрифт, радиус, плотность — как в коде, не «как у всех» |
| **Patterns** | 3–7 приёмов этого UI (список vs карточки, шапка, формы, пустые состояния) |
| **Motion** | Что двигается и чего не делать (или «почти без motion») |
| **Don't** | Запреты продукта + anti-slop, если здесь часто срываются |
| **Exceptions** | Лого, маркетинговый мир, RTL, отдельный лендинг — только факты |

**Условный раздел «Чеклист ревью UI»:** только если в репо уже был отдельный продуктовый чеклист (`UI_UX_GUIDELINES.md` и т.п.) — **вклеить сюда**. Иначе раздел не заводить. Не оставлять пятый файл и не оставлять указатель.

Пишет `/MA-revise-project` (каркас) и `/MA-design-screen` (уточняет после экрана).
