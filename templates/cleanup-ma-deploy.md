# Уборка мусора в `/MA-deploy` (Phase 3.8 + 7.6)

**Цель:** сам инициировать очистку локального мусора — без отдельной просьбы «удали мусор». Два прохода: **до упаковки** (не тащить в релиз) и **после прода** (хвост этого прогона).

**Только из `/MA-deploy`**. Не отдельный GitHub Action.

## Два прохода

| Проход | Phase | Зачем | Когда |
|--------|-------|--------|--------|
| **Ранний** | **3.8** | Старый мусор и ключи в `tmp` не едут рядом с commits/push | После зелёных 1–3.5, **до** 3.9. Есть и в `check-only` |
| **Поздний** | **7.6** | Хвост **этого** деплоя (smoke PDF, скрины, логи) | После 7.5. Skip при `check-only` / `skip-merge` |

Тихий skip «мусора нет, и не смотрел» **запрещён** на каждом проходе — скан + «мусора не нашёл» или список.

Прод **не** откатывать из‑за уборки.

## Что искать (ориентир, не жёсткий чеклист)

Агент **сам** оценивает корень продукта. Ориентиры:

| Класс | Примеры | Обычно |
|-------|---------|--------|
| UI / дизайн-сессии | `.impeccable/`, локальные скриншоты ревью | safe junk |
| Временные артефакты | `tmp/`, `tmp/*.pdf`, smoke-логи, sync-логи | safe junk |
| Кэши тестов / e2e | `playwright-report/`, `test-results/`, `coverage/` | safe junk (если не в git) |
| Скриншоты / записи | `*.png`/`*.webm` в tmp, `__screenshots__` | safe junk |
| Похоже на секреты | `*api-key*`, `*secret*`, `*.pem` в `tmp/`, токены вне `.env*` | **всегда спросить** |
| Не трогать без явного «да» | `.env`, `.env.local`, `node_modules/`, `.git/`, исходники в git | запрет |
| Диск / билд | `.next/` / `.turbo` — Phase 3; в 3.8/7.6 не чистить по умолчанию | спросить при тесном диске |

**3.8 акцент:** секреты, раздутый `tmp`, leftover прошлых сессий — всё, что не должно лежать рядом с упаковкой релиза.  
**7.6 акцент:** артефакты, появившиеся **в этом** прогоне после 3.8 (smoke, скрины, новые логи). Не повторять длинно то, что уже закрыли в 3.8, если ничего нового.

Local deviations в `AGENTS.md` — доп. «всегда чистить» / «никогда не трогать».

## Классификация

1. **Safe junk** — явно временное, не секреты, не в git (или только ignored).
2. **Secret-looking** — похоже на ключ/токен/pem. **Не** печатать содержимое в чат.
3. **Ask** — польза неочевидна.

Показать: путь · что это · размер (примерно) · класс.

## Режимы (оба прохода)

### safe (и без `auto`)

1. Скан → список. Пусто → «мусора не нашёл» → дальше по pipeline.
2. Есть → **всегда спросить** A/B/C (+ рекомендация). Удалять только после ответа.

### auto

1. Скан → список.
2. **Safe junk** — удалить без спроса; перечислить «уже удалил: …».
3. **Secret-looking** и **Ask** — **всегда спросить**, даже в `auto`.

## Формат вопроса (эталон)

```
Уборка перед упаковкой релиза (или: после релиза):

1. .impeccable/ — скриншоты UI (~2 MB), не в git
2. tmp/ — старые логи
3. tmp/…-api-key.txt — похоже на ключ (содержимое не показываю)

Что удалить?
Рекомендую: всё безопасное + файл с ключом.
A) всё  B) только безопасное, ключ оставить  C) только ключ / ничего
```

Подстроить A/B/C под фактический набор.
