# Simplify в `/MA-product-pass` (B2 + C3)

**Цель:** зона читается как код аккуратного человека — следующий разработчик понимает кусок **по именам и форме**, без комментария-пересказа.  
**Мантра:** **убери ИИ-стиль**.

**Только из `/MA-product-pass`.** Релиз (`/MA-deploy`) упрощает через **ponytail**, не этот эталон.

## Когда

| Шаг | Scope | Обязателен? |
|-----|--------|-------------|
| **B2** (каждый модуль) | зона модуля из плана | да, всегда после B1 |
| **C3** (после всех модулей) | стыки + накопленный diff прогона | да, **узкий** — не второй полный B2 |

Пропуск «правок мало» **запрещён**. Если словарь не сработал — в отчёте: «смотрели, ИИ-шума не нашли».

## Что улучшить в идее (закон)

Жёстко = **срезать шум и выровнять локальные имена**, а не «переписать модуль под человеческий стиль».

| Делать сразу | Не делать молча → backlog |
|--------------|---------------------------|
| Комментарии-пересказ, мёртвое, одноразовые обёртки, канцелярит **внутри** зоны, дубли state, ложный memo | Смена **контракта**: URL, публичный export наружу зоны, колонки БД, ключи i18n, payload вебхука, CSS-классы из доки |
| Переименовать `handleData` → `saveOrder`, если все вызовы в зоне (или правка call-site в зоне) | Новые файлы / «слой домена» ради читаемости |
| Сжать простыню **на месте** | Вырезать проверки на границе доверия (вход, роли, деньги, RLS) как «оборонительный шум» |

«Выглядит по-ИИшному, но вдруг задумано» — не отговорка для **шума**. Для **контракта** — отговорка как раз нужна: в backlog.

## Порядок внутри B2 (не наоборот)

1. Срезать шум (комменты, мёртвое, пустые обёртки, секции `====`).
2. Выровнять имена на **glossary** продукта (не выдумывать «красивые» синонимы).
3. Инлайн одноразового; схлопнуть копипасту в **один понятный путь**.
4. Только потом — типы и React-церемония.
5. **Не** заводить новые абстракции в том же проходе, где только что инлайнил.

## Словарь ИИ-приёмчиков (обязательный чеклист, 12)

Пройти **все** пункты. В отчёте — номера + 2–3 «было → стало» простым языком.

1. **Комментарии-пересказ** — `// get the user`, очевидный JSDoc, «As an AI». Удалить. Оставить только *почему* / инвариант / опасный край.
2. **Одноразовые helpers** — `getX`/`buildY` с одним вызовом. Инлайн. Второй call-site — тогда оставить.
3. **Слой «на будущее»** — Abstract/Base/factory с одной реализацией, options из одного поля. Схлопнуть **в существующий** файл, не в новый «архитектурный» слой.
4. **Оборонительный шум** — широкий `try/catch`, optional chaining там, где тип уже есть, `if (x) if (x)` . Убрать. **Не трогать** проверки на входе, сессии, правах, деньгах, RLS.
5. **Слабые типы** — `any`, пустой `as`, `!` «заткнуть компилятор». Нормальный тип или один узкий cast с причиной.
6. **Канцелярит в именах** — `handleData`, `processItem`, `doStuff`, голые `utils`/`helpers`/`manager` без домена. → язык продукта (`saveOrder`, `workspaceId`). Не переименовывать уже каноничные доменные `*Service`, если имя совпадает с glossary.
7. **Синонимы сущностей** — два слова на одну сущность glossary. Выровнять на канон, не на «более человеческое».
8. **Церемониальный React** — `useMemo`/`useCallback`/`memo` без цены или стабильности; `useEffect` вместо расчёта в рендере. Снять. **Оставить** callback/memo, если проп уходит в уже мемоизированного ребёнка (иначе регресс).
9. **Простыни** — длинная оркестрация, огромные props. **Сжать на месте.** Новый файл — только если граница уже есть в папках модуля (не плодить `XUtils` / `XManager`).
10. **Шаблонный шум** — `====`, emoji в коде, пустые wrappers, state = копия props. Удалить.
11. **Копипаста** — два почти одинаковых блока. Один путь. Не «generic engine».
12. **Мёртвое** — unused export, флаг который никто не ставит, fallback «на всякий». Удалить.

### Это не ИИ-стиль (не резать)

- `never` в `default` switch (закон хаба)
- импорты сверху файла
- деньги целыми минимальными единицами, не float
- явные проверки сессии / RLS / роли
- имена из glossary, даже если длинные
- сгенерированное, миграции, вендор, `.env`

### Было → стало (ориентир)

- `handleData(item)` + `// save the order` → `saveOrder(order)` без комментария
- `createUserServiceFactory({ deps })` с одной реализацией → прямые функции в том же модуле
- `useMemo(() => items.filter(...), [items])` без тяжёлой работы → `.filter` в рендере

Антипример: `processItem.ts` → `ItemOrchestrator.ts` + `ItemHelpers.ts` — это **хуже**, не чистка.

## Полноценный прогон

1. Scope: пути / символы / diff зоны.
2. Три read-only субагента **параллельно** (только findings). Brief: **«убери ИИ-стиль»** + словарь + таблица «делать / не молча» + «это не ИИ-стиль»:
   - **качество:** 1–7, 9–12;
   - **perf:** hot path, N+1, болтливые логи, пункт 8 (ложный memo) с оговоркой про мемоизированных детей;
   - **reuse:** пункт 11 + уже есть хелпер в репо; не изобретать framework.
3. Сам агент применяет словарь **по порядку** выше, поведение пользователя сохранить.
4. Контракт / граница доверия / новый файл «для архитектуры» → backlog. Шум и локальные имена — не в backlog.
5. Лёгкий lint/typecheck/тесты зоны, если дёшево.
6. Отчёт **Анти-ИИ:** номера 1–12; 2–3 «было → стало»; что ушло в backlog как контракт.

Несвязанные правки пользователя не трогать. B2 не уезжает в другие модули плана.
