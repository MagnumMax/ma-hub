# llms.txt — эталон

Файл **для внешних языковых моделей**: что это за продукт и какие страницы читать, не парся HTML.

**Кто пишет:** только `/MA-seo-geo-audit` (skill `seo-geo-audit`, трек GEO + структура + P0-страницы).  
Сверка, идея, дизайн, выкат — **не** сочиняют этот файл. Нет аудита → нет живой карты (можно пустое место; не заглушка «Home https://example.com»).

**Куда класть:** сначала найти существующий роут/генератор (`**/llms.txt/route.*`, `*llms-txt*`). Если есть — править **его**, не класть `public/llms.txt`. Если нет — `public/llms.txt` при наличии `public/`, иначе корень. Один источник.

**Формат файла:** [llmstxt.org](https://llmstxt.org/) — H1, цитата-описание, списки ссылок.  
**Смысл текста:** чеклист GEO `$MA_HUB_ROOT/skills/seo-geo-audit/references/geo-content-checklist.md` + контракт сборки `skills/seo-geo-audit/references/llms-txt.md`.

## Обязательные разделы (после аудита)

| Раздел | Что должно быть |
|--------|-----------------|
| **H1** | Каноническое имя продукта (как на сайте, без путаницы с чужим брендом) |
| **Цитата `>`** | Короткий ответ: что это / для кого / зачем (2–4 предложения, можно процитировать целиком) |
| **Факты** | Конкретика с аудита (цифры, география, условия) — без выдумки; нет факта — не писать |
| **Это не** | Дизамбиг, если ИИ может спутать |
| **Docs** | Ссылки на markdown (README, при необходимости DESIGN) |
| **Pages** | Только **реальные** URL выбранной среды: P0 + то, что ИИ должен открыть. У каждой — одна строка, что там узнать |
| **Optional** | Второстепенные ссылки; агент может пропустить |

Запрещено: localhost как «публичный» адрес для цитирования; выдуманные URL; копипаст всего README; пароли.

Черновик файла — в отчёте аудита. На диск — после «ок» / «чини» (по умолчанию **да, обновить llms.txt**). Режимы без GEO (`tech`, `structure`, `authority`) — файл не переписывать, если не попросили.
