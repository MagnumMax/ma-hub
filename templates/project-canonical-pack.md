# Канон-файлы продукта

В каждом продукте — **четыре файла**. Отдельный `docs/MA-STANDARDS.md` больше не нужен.  
Сами правила живут в хабе (`standards/`). В продукт **не копировать** папку `standards/`.

| Файл | Для кого | Кто заполняет | Эталон «что внутри» |
|------|----------|---------------|---------------------|
| `README.md` | люди | сверка / руками | `templates/project-readme.md` |
| `AGENTS.md` | агенты в репо | сверка / руками | `templates/project-agents.md` |
| `DESIGN.md` | агенты на UI | сверка + `/MA-design-screen` | `templates/project-design.md` |
| `llms.txt` | внешние ИИ (ChatGPT, Perplexity, AI Overviews…) | **только `/MA-seo-geo-audit`** | `templates/project-llms.txt` + skill `seo-geo-audit/references/llms-txt.md` |

Не оставлять файл из одного заголовка. Каждый раздел из эталона — либо заполнен, либо явно «не применимо» (одна строка почему).

## Первый проход — сразу, не «потом»

Когда создаёшь или дописываешь тройку, в **том же пакете** (после «ок» на план):

1. Найти уже существующие файлы вида `UI_UX_GUIDELINES.md`, `docs/design-system.md`, `docs/MA-STANDARDS.md` и похожие guidelines.
2. Уникальное продуктовое → в `DESIGN.md` (в том числе чеклист ревью UI) или в `AGENTS.md`.
3. **Заменить ссылки** на каждый поглощённый файл (см. ниже) — до удаления.
4. Старый файл **удалить**. Не оставлять файл из одной строки «см. DESIGN.md», если на него ссылается только архив.

Не предлагать отдельной следующей задачей «перенести чеклист», «убрать указатель» или «починить ссылки», если исходники уже найдены в этом прогоне.

## Замена ссылок (обязательно)

После переноса содержимого — **поиск по имени старого файла** по всему репо (не только рядом с ним). Для каждого попадания:

| Где нашли | Что сделать |
|-----------|-------------|
| Живые доки, `AGENTS.md`, `README.md`, handbook, `.cursor/rules`, скрипты, комментарии в коде | Заменить на канон (`DESIGN.md` / `AGENTS.md`) и нужный раздел, если он есть |
| `git add` / CI / путь в команде | Заменить путь на канон, иначе сборка или скрипт сломается |
| `_archive/` / `legacy/` | Не переписывать историю. Если это **единственные** оставшиеся ссылки — всё равно удалить старый файл, stub не оставлять |

Пока живые ссылки не заменены — **не** удалять файл. После замены — повторный поиск: в живой части имени старого файла быть не должно.

Канон в ссылке: тот файл, куда ушло содержимое (чеклист UI → `DESIGN.md`, визитка MA → `AGENTS.md`).

## Указатели

Файл-указатель (одна строка «см. X») — **исключение**, не норма.

Оставить только если что-то **требует этот путь** (скрипт, CI, генератор, внешний инструмент).  
Архив `_archive/` / `legacy/` — замороженная история: имена старых файлов можно не переписывать; **не** держать живой stub ради битых ссылок в архиве.

`docs/MA-STANDARDS.md`: после переноса в `AGENTS.md` — **удалить**. Одна строка «см. AGENTS.md» — только если что-то ещё открывает этот путь.

## Где лежит `llms.txt`

Перед записью на диск — **найти, не отдаётся ли уже `/llms.txt`:**

- роут вроде `**/llms.txt/route.*`
- модуль вроде `*llms-txt*`, `llmsTxt`

| Что нашли | Что делать |
|-----------|------------|
| Генератор / App Router route | Править **его** (и тесты, если есть). **Не** класть `public/llms.txt` — будет два источника |
| Ничего | `public/llms.txt` если есть `public/`, иначе корень. Один файл |

«Файл есть» = статика **или** живой роут. Проверка: открыть `/llms.txt` на выбранной среде, не только glob в `public/`.  
В `AGENTS.md` (Layout) написать, откуда берётся карта, если это не статический файл.

## Не затирать уникальное — но дыры закрывать

| Файл | Если уже есть |
|------|----------------|
| `README.md` | Не сносить живой текст. Дефолт Next/Vite («bootstrapped with…») — заменить по эталону. Недостающие **обязательные разделы** — дописать. |
| `AGENTS.md` | Дописать блок Monster Automation и пути релиза; не сносить чужие команды/запреты. Недостающие разделы — дописать. Блок вроде `<!-- BEGIN:nextjs-agent-rules -->` (его снова пишет `next dev`) — **оставить сверху**, канон MA — **после** него. |
| `DESIGN.md` | Не затирать бренд. Недостающие разделы — дописать. Продуктовый UI-чеклист из другого файла — **вклеить сюда**, не плодить пятый файл. |
| `llms.txt` | Не выдумывать URL. Переписывает **аудит**, не сверка «на глаз». Если карта генерируется кодом — править генератор, не заводить второй файл. |

## Когда обновлять

| Файл | Когда |
|------|--------|
| `README.md` | Смысл продукта, для кого, запуск или роли изменились. |
| `AGENTS.md` | Сверка; новые команды/запреты; новый пользовательский путь → строка в обязательные пути. |
| `DESIGN.md` | Новый экран или смена токенов/запретов (`/MA-design-screen`). Чеклист UI изменился — здесь же, не отдельным файлом. |
| `llms.txt` | После `/MA-seo-geo-audit` (режимы с GEO). Сверка только отмечает: нет файла **и** нет роута / заглушка / расхождение с P0 — и предлагает аудит. Не на каждый мелкий фикс. |

## Ворота `/MA-*`

Найди хаб (`MA_HUB_ROOT`).

**Тройка обязательна:** `README.md`, `AGENTS.md`, `DESIGN.md` (разделы по эталонам, не пустые заголовки). Старый `docs/MA-STANDARDS.md` без `AGENTS.md` = тройки нет.

**`llms.txt`:** четвёртый файл **или** живой роут, который его отдаёт. Пишет `/MA-seo-geo-audit`. Нет ни файла, ни роута, или одна заглушка без фактов/страниц = пробел GEO, не повод выдумывать карту в другой команде.

### Нет тройки

Объясни зачем (люди / агент / вид). Предложи создать из эталонов `project-readme.md`, `project-agents.md`, `project-design.md`.

Спроси: «Создать README, AGENTS.md, DESIGN.md? **ок** / позже».

| Команда | До ок / «позже, всё равно продолжай» |
|---------|----------------------------------------|
| `/MA-idea-to-plan`, `/MA-design-screen`, `/MA-deploy` | **стоп** |
| `/MA-seo-geo-audit` | стоп **только** если нет хаба; тройка — предложить, аудит можно после «ок»/«позже» (иначе не из чего собрать карту для ИИ) |
| `/MA-product-pass` | можно продолжать после «ок» или «позже» |
| `/MA-revise-project` | аудит всё равно; создание тройки — первый пункт плана |

После создания — читай `AGENTS.md` и `DESIGN.md`.

### Тройка есть, `llms.txt` нет или заглушка

Ритуал **не** стопать (кроме желания пользователя сначала закрыть GEO). В итоге: «карту для внешних ИИ собирает `/MA-seo-geo-audit`» + среда/URL.  
`/MA-deploy` — не блокер релиза (обязательные пути живут в `AGENTS.md`); в отчёте ⚠️ если публичный сайт без живого `/llms.txt` (ни файла, ни роута).

### `/MA-deploy`: нет обязательных путей — стоп

Список **только** в `AGENTS.md`, заголовок ровно `## Обязательные пути релиза`. Эталон: `release-must-work-paths.md`.

Списка нет: нет заголовка / пустая таблица / меньше **2** строк `always` / заглушки `…`.

**Не** начинай Phase 0/1. **Не** запускай `/MA-revise-project` из выката.

1. Покажи черновик 5–10 путей этого продукта.
2. Спроси: **дописать здесь** / **сначала сверка**.
3. «Дописать здесь» → вписать в `AGENTS.md`, не коммитить до Phase 3.9.
4. «Сначала сверка» → стоп.
5. Тройка сильно отстала → в рекомендации сверка, ждать ответ.

`check-only` / `skip-merge` — тот же стоп без путей.

## Миграция со старой визитки

Если есть `docs/MA-STANDARDS.md`: pin, отклонения, пути → `AGENTS.md`. Поиск по имени файла → заменить живые ссылки → после «ок» **удалить** (указатель — только если путь ещё нужен, см. выше).  
`docs/design-system.md` / `UI_UX_GUIDELINES.md` → уникальное в `DESIGN.md` → заменить живые ссылки → удалить исходник (не указатель «на всякий случай»).

## Дубли правил

Копии стандартов хаба → перенести уникальное в `AGENTS.md` / `DESIGN.md`. Удаление только после «ок».  
Дефолт после переноса — заменить живые ссылки, **удалить** файл, не оставлять stub. Ссылка на месте старого пути — только если этот путь кто-то ещё требует.
