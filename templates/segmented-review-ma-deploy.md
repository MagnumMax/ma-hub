# Ревью волны в `/MA-deploy` (Phase 0W + 1A)

**Цель:** перед продом один внимательный взгляд на **то, что уезжает сейчас** — не средний проход по всей грязной папке и не семь проходов по кускам одной темы.

**Только из `/MA-deploy`.** Не открывать ветки и GitHub PR «на кусок». Закон релиза: одно дерево → атомарные commits **только выбранной волны** (3.9) → один push `dev` → один PR в `main`. Хвост следующих волн остаётся в дереве (после проверок его возвращают, если прятали).

## Diff scope

Uncommitted + при необходимости `main..HEAD` (кандидат в релиз). Не ждать Phase 3.9.

**Волна** — что уезжает в **этом** `/MA-deploy` (один push → один PR). Это единица ревью, упрощения и упаковки. Нарезка волны на сегменты / куски для ревью **запрещена**.

## 0W — Волны (выбор темы)

1. Разложить весь diff scope по **зонам продукта** (вход, кабинет, отчёты, хвост прошлой работы…). Строки = added+deleted (`git diff --numstat` + оценка untracked).
2. **Две и больше независимых темы** → это **несколько выкатов**, не один проход.
   - Таблица волн (зона / ~строк / что внутри простыми словами / рекомендуемый порядок: фундамент раньше).
   - **Стоп** — ждать, какую волну выкатывать **сейчас**. Даже `auto`: это бизнес-решение, не «заодно всё».
   - Не выбранная волна: **не** ревьюить, **не** упрощать, **не** коммитить в 3.9.
3. Одна связная тема (даже большая) → одна волна, сразу 1A. Маленький diff → одна волна, тот же один цикл 1A.

Не дробить одну связную фичу на два выката только из‑за объёма.

## 1A — Один цикл на выбранную волну

Жёсткий порядок **один раз на волну**: **`/code-review` (+ bugbot/security по типу темы) → Critical/High fix → ponytail + автофикс → backlog**.

Scope = файлы **этой** волны. Не весь грязный ком. Не нарезать таблицу кусков.

Показать коротко: зона / ~строк / **Область** (для `if-touched`) / ревью сверх `/code-review` по A1 — и сразу идти (без «ок?» на план кусков). Пауза только на выбор волны (0W) и бизнес-решения позже.

### A1. Ревью по типу темы (волна целиком)

Приоритет находок: баги → регрессии → безопасность → пробелы в тестах.  
Гонять **только эту волну**, не чужие темы и не «весь diff скопом включая отложенное». Не спрашивать «какое ревью запустить».

| Что | Когда |
|-----|--------|
| **`/code-review`** | **Всегда.** Костяк волны. В A2 критичное чинить (закон выката сильнее «не правь код» у самой команды). |
| **`review-bugbot`** | Волна меняет **поведение**: логика, поток экрана, API, данные, состояние. Не гонять на правку только текстов / копирайта. |
| **`review-security`** | Волна про **вход, роли, платежи, персональные данные, секреты**. Даже если уже был `/code-review`. |

Оба специалиста на одной волне — нормально (поведение + доступ). Все три на правку текста — запрещено. Каждый специалист — **не больше одного** прохода на волну.

**Запрещено:**
- нарезать волну на сегменты «чтобы ревью было внимательнее»;
- вызывать `/review` (меню «Bugbot или Security»: пауза и только одно из двух);
- подменять `/code-review` парой специалистов;
- гонять Bugbot/Security/ponytail на чужие волны «заодно»;
- считать Bugbot/Security заменой ponytail (A3).

Нет файла skill на диске → блокер (Cursor-native / кэш skills). Findings — по серьёзности, в чат. Critical/High из любого прохода → A2.

### A2. Сразу чинить Critical и High

- **Даже в safe** — для этой волны: Critical/High в дереве без паузы «чини?».
- Не уезжать чинить **другую** волну «заодно» / «чтобы typecheck стал зелёный».
- После фиксов — лёгкая проверка по затронутому (если дёшево).

### A3. Ponytail + автофикс (один раз на волну)

**Отдельный проход, не часть code-review.** Ревью на ошибки / security / bugbot **не** заменяет. Глубокая уборка всего продукта — `/MA-product-pass`, не этот шаг.

1. Прочитать skill `ponytail-review` с диска (нет файла → блокер `install-external-skills.sh`). **Прочитать / поставить skill ≠ прогнать.**
2. Прогнать по **diff этой волны** (не всего грязного дерева, не по кускам). Формат findings — как в skill.
3. Показать findings **в чате**: строки `L…: <tag> …` **или** буквально `Lean already. Ship.`
4. **Сразу применить** явные `delete` / `stdlib` / `native` / `yagni` / `shrink` в дереве (без commit).  
   Исключение MA-deploy: skill «только отчёт» — здесь агент **вносит** правки.
5. Спорное / «нужно бизнес-решение» — **не** резать молча → в backlog.
6. **Одна строка доказательства** на волну (таблица 2b). Без строки — не 1B.

| Волна | net | Внесено явно | В backlog |
|-------|-----|--------------|-----------|
| … | `net: -12` или `Lean already. Ship.` | 2 (delete, shrink) / 0 | нет / 1 спорное |

Минимум: `net: -<N>` **или** `Lean already. Ship.` Плюс сколько явных правок (0 только если lean / `net: 0`).

**Не доказательство:** «прочитал skill»; «ревью чистое»; «нечего упрощать» без `Lean already. Ship.` / `net: 0`; пустая таблица 2b.

**Safe:** после автофикса, если оставшийся заявленный `net ≤ -80` → стоп, ждать решения.  
**Auto:** пометить и продолжить (строка всё равно обязательна).

### A4. Backlog волны

- Medium / Low из code-review;
- спорные ponytail без автофикса;
- кратко: файл / суть / рекомендация (чинить / отложить).

## После 1A — сводный backlog

Показать таблицу решений (простым языком).

**Safe:** пауза «чини / не чинить / отложить» (пакетом ок). Пустой backlog или «всё отложить» → 1B **только если** есть строка 2b.  
**Auto:** дешёвые однозначные Medium — починить; остальное в отчёт → 1B **только если** есть строка 2b.

**Gate до 1B:** одна строка доказательства на выбранную волну. Дыра → стоп, не typecheck/lint/tests, не 3.9, не push.

**Дыру нашли позже** (уже 1B / упаковка, ещё не push): не выкладывать. Снова A3 по **этой** волне → если код менялся, снова 1B → 3.8/3.9 заново, если уже упаковывали.

## Чужие волны не блокеры (изоляция)

Ошибки typecheck / lint / test / build, которые живут в **файлах другой волны**, **не** стоп этого выката и **не** повод чинить чужую тему.

Если suite красный из‑за них: **спрятать** пути других волн (`git stash push -u -- <пути>`, включая untracked) на время 1B–3.9 → прогнать проверки и упаковать **волну** → **вернуть** stash. Не выбранная работа должна снова лежать грязной в дереве.

Нельзя: чинить штрафы, чтобы выложить документы; считать «красное всё дерево» блокером выбранной темы.

## Запреты

- Нарезка волны на сегменты / куски для ревью, ponytail или специалистов.
- Ветки / push / GitHub PR на кусок.
- Полный test suite несколько раз «на всякий случай» (suite — один раз в 1B, на изолированной волне).
- Commit до Phase 3.9; в 3.9 — файлы **вне** выбранной волны.
- Смесь независимых зон в одном выкате без выбора волны.
- Ревью / ponytail / специалисты на весь грязный ком включая отложенные темы.
- Считать «прочитал skill» / «ревью без замечаний» доказательством ponytail.
- Идти в 1B / 3.9 / push без строки 2b на волну.
- Чинить другую волну, чтобы проверки стали зелёные.

## Отчёт (минимум в таблицах `/MA-deploy`)

- Волна: какая зона сейчас / что отложено; ~строк; Область для путей.
- Critical/High закрыты? Какие специалисты были (— / bugbot / security / оба).
- **Одна** строка ponytail (`net` или `Lean already. Ship.` + сколько явных правок).
- Сводный backlog и статус решений.
- Чужие волны: спрятаны на время проверок? возвращены после 3.9?
- Пустая таблица 2b = блокер, не «пропуск».
