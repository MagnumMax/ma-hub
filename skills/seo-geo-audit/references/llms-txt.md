# llms.txt — сборка из SEO+GEO аудита

Пишет только оркестратор `/MA-seo-geo-audit` / skill `seo-geo-audit`.  
Спецификация имени и порядка секций: [llmstxt.org](https://llmstxt.org/).  
Смысл: внешняя модель должна **понять продукт и пройти по ссылкам**, не высасывая весь HTML.

Не заменять трек `geo-content-optimizer`: сначала **Read** его `SKILL.md` (audit-only), затем собрать этот файл из доказательств аудита.

## Когда собирать

Режимы с GEO: `full`, `page`, `quick`, `pre-deploy`, `post-deploy`.  
Не трогать файл в `tech` / `structure` / `authority`, если пользователь не попросил.

## Откуда брать текст (не выдумывать)

| Кусок llms.txt | Откуда |
|----------------|--------|
| Имя, «что это / для кого» | On-page + GEO на главной/денежной: H1, title, quotable 2–4 предложения |
| Факты | Только Measured / User-provided с аудита. Estimated — не в файл |
| «Это не» | GEO / competitor: путаница брендов, если всплыла |
| Pages | P0 + структура сайта; URL **primary base**. Local: реальные local/preview URL **или** только Docs, если публичных нет. **Не** выдавать `localhost` за индекс Google / цитату в проде |
| Docs | `README.md` (и `DESIGN.md`, если помогает понять продукт) |
| Optional | Вторичные страницы из структуры; конкурентов сюда **не** класть |

Чеклист «можно цитировать»: `geo-content-checklist.md` (обязательные 1–8). Дыры чеклиста — в бэклог аудита, не замазывать красивым llms.txt.

## Куда писать

Сначала поиск в репо: уже есть роут или генератор (`**/llms.txt/route.*`, `*llms-txt*`, `llmsTxt`)?

| Нашли | Действие |
|-------|----------|
| Да | Обновить генератор (и тесты). **Не** создавать `public/llms.txt` — два источника. В отчёте: «карта живая через роут …» |
| Нет | Как `templates/project-canonical-pack.md`: `public/llms.txt` или корень. Один файл |

«На диске нет файла» ≠ «карты нет»: открыть `/llms.txt` на выбранной среде. Localhost в Pages не выдавать за публичную цитату.

## Порядок в файле

1. `# Имя`
2. `> описание` (quotable)
3. Абзац фактов и «это не» — без новых H2, если так проще уложиться в spec (после blockquote до первых `##` — обычный markdown без заголовков)
4. `## Docs` — список `[имя](url): зачем`
5. `## Pages` — то же для страниц продукта
6. `## Optional` — только если есть что отдать «на потом»

Ссылки должны вести на **markdown-friendly** цели: страницы сайта и `.md` в репо. Не ссылаться на выдуманный `.html.md`, если его нет.

## В отчёте аудита

Показать **предложенный** `llms.txt` целиком (или diff к текущему).  
На диск — после «ок» / «чини»; в этом вопросе пункт **обновить llms.txt** по умолчанию **да**. Если карта уже из роута — править генератор.  
Не писать отчёт аудита в `memory/`, пока пользователь не попросил файл отчёта.

## Local vs prod

| Среда | URL в Pages |
|-------|-------------|
| **local** | URL primary base (preview/localhost) для людей/агента в репо; в цитате не обещать «нас уже цитирует ChatGPT». После выкладки — повтор `quick prod` / `post-deploy`, чтобы подставить боевые URL |
| **prod** | Только живые публичные URL, которые аудит реально открыл |

Пустой Pages лучше, чем фейковый `https://example.com/`.
