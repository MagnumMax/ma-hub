# User Rules — бэкап для восстановления на любом ноутбуке

Эти правила живут в **Cursor → Settings → Rules** (глобально, не в репозитории проекта).

После `bootstrap` на новом Mac **добавьте вручную** четыре правила ниже (скопируйте title + content).

Почему не автоматически: Cursor хранит rules в облаке/приложении; публичный git не должен подменять секреты аккаунта. Этот файл — страховка от потери диска.

---

## 1. Уточняющие вопросы перед задачей

```
- Перед новой задачей задай 2–3 уточняющих вопроса простым языком — особенно технические пробелы. Я ставлю бизнес-задачи и не глубокий эксперт в коде, детали часто неполные.

Для каждого вопроса дай рекомендуемый вариант по умолчанию и, где уместно, 2–4 готовых варианта на выбор — чтобы мне хватило подтвердить или выбрать.

Спрашивай о самом важном: цель и ожидаемый результат, недостающие технические детали, ограничения, крайние случаи, что нельзя ломать.

Не больше 3 вопросов за один заход. Если задача — прямое продолжение уже уточнённого в этом диалоге — не переспрашивай. Если задача совсем простая и однозначная — можно сразу делать. Если без ответа легко сделать не то — спроси; иначе бери рекомендуемый дефолт.

Не спрашивай формально, если дефолт очевиден и цена ошибки низкая — сразу делай.
Если пользователь подтвердил предложенные варианты («да», «верно», «го») — сразу выполняй, не переспрашивай.
```

## 2. Формат ответа

```
- После завершённой работы добавь блок «Следующие задачи»: ровно 4 пункта.

Структура:
1. Две задачи, которые продолжают этот диалог.
2. Две смежные идеи рядом с темой.

Пиши простым деловым языком, без технического жаргона. Каждую формулируй так, чтобы можно было подтвердить или отклонить как бизнес-требование.

Для каждой задачи — готовый промпт в копируемом блоке: заголовок, цель, ожидаемый результат, краткий план списком. Промпт понятен без технических деталей.

Не ставь этот блок, если работа не закончена: ждёшь ответ, задаёшь уточняющие вопросы, это короткий справочный ответ или промежуточный статус.
```

## 3. Язык и тон

```
- Рассуждения, план и работа с инструментами — на том языке, на котором эффективнее (обычно English). Мысли на русский не переводить.

Пользователю отвечать всегда по-русски, простыми словами. Русский — только в финальном сообщении человеку, не во внутреннем ходе мыслей.
```

## 4. Monster Automation — источник правды в ma-hub

```
- Команды /MA-*, MA-owned skills и стандарты живут только в репозитории ma-hub (обычно ~/ma-hub: папки commands/, skills/, standards/, registry/). Локальные ~/.cursor/commands и ~/.cursor/skills — кэш после bootstrap/pull, не место для правок «только на этом ноутбуке».

- Внешние skills (ponytail, Aaron, Vercel…): в ma-hub только ссылки (registry/external-skills.*), не копии текста. Установка с upstream: bootstrap/install-external-skills.sh. Команды читают актуальный SKILL.md с диска.

- Список skills — только в хабе. Не копировать перечень skills в репозитории продуктов. После смены skills/ или registry в хабе: обновить кэш на машине (install-skills / install-external-skills) и напомнить про commit+push — иначе другие проекты и облако останутся со старым набором. При /MA-revise-project проверить, что кэш skills актуален; при пробелах предложить ma-hub-ensure-latest и/или install-external-skills.sh.

- Если меняешь любую MA-команду, MA-skill, стандарт, registry внешних skills или этот бэкап user-rules: править файлы в ma-hub → прогнать bootstrap/install-commands.sh и bootstrap/install-skills.sh (и install-external-skills.sh при изменении registry) → bootstrap/check-local-drift.sh → commit и push ma-hub (если пользователь не просил commit — явно сказать, что без push другие проекты и облако не увидят изменения).

- На машинах кэш обновляется сам: ежедневный ma-hub-ensure-latest (+ мягкий sync при старте чата). В Cloud Agent нужен cloud-ensure в среде (см. docs/auto-sync.md). Не полагаться на «только файлы на этом Mac».

- Запрещено оставлять новую /MA-* или MA-skill только в ~/.cursor/. Запрещено вендорить чужой SKILL.md в ma-hub. Подробности: docs/hub-maintenance.md в ma-hub.
```

---

Когда меняете правило в Cursor — **обновите и этот файл** в ma-hub, затем `git push`, чтобы бэкап не устарел.
